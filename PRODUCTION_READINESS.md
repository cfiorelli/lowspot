# Production Readiness

lowspot is currently suitable for private alpha testing with allowlisted Spotify users. It is not yet ready for broad public distribution.

## Ready For Private Alpha

- Text-first lean and expanded UI exists.
- Spotify PKCE login uses a loopback desktop callback.
- Library hydration is capped to avoid full-account request bursts.
- Spotify 429 cooldowns are persisted per endpoint/client and shown in Settings/status log.
- Web Playback SDK connection is opt-in, not startup behavior.
- Mock mode supports UI development without Spotify API calls:
  ```bash
  npm run tauri:dev:mock
  ```
- macOS DMG builds are generated by Tauri.

## Not Production Ready Yet

- App is unsigned and not notarized.
- No auto-update channel.
- No extended Spotify quota approval.
- Development-mode Spotify apps are limited to allowlisted users.
- Live playback/device targeting still needs verification once Spotify access recovers.
- Settings diagnostics are useful but still developer-oriented.
- No automated UI test suite yet.

## Highest-Risk Areas

1. Spotify quota/rate limits
- Mitigated by capped hydration, persisted cooldowns, mock mode, and opt-in SDK.
- Remaining risk: live testers may still trigger unexpected endpoint-specific limits.

2. Playback device targeting
- Open bead: `lowspot-mx2`.
- Requires live Spotify testing with a healthy token/client before closing.

3. Distribution trust
- Unsigned apps create Gatekeeper friction.
- Signing/notarization is the next real financial/operational step before public users.

## Recommended Next Steps

1. Wait for Spotify cooldown/app-creation limits to clear.
2. Create one fresh Spotify Developer app and add only required redirect URIs.
3. Run one live smoke test:
   - Login
   - One Liked Songs page
   - One search
   - One playback command on an existing active device
4. Close or update `lowspot-mx2` based on live playback behavior.
5. Prepare a private alpha DMG and test with one allowlisted user.
6. Decide whether to invest in Apple signing/notarization.

## Pre-Alpha Gate

Before sending a DMG to anyone:

- `npm run typecheck`
- `npm run lint`
- `npm run build`
- `npm run build:mock`
- `npm run tauri:build`
- Confirm `.env` is not committed.
- Confirm `.env.example` does not contain a real Client ID.
- Confirm the Spotify app contains `http://127.0.0.1:7878/callback`.
- Confirm the tester is allowlisted in the Spotify app.
